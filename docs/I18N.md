# AFG AI internationalization contract

## Supported locales
- Dari (Afghanistan): `dari`, BCP-47 `fa-AF`, RTL.
- English (United States): `english`, BCP-47 `en-US`, LTR.
- Pashto and Arabic are intentionally not exposed yet. They must not appear in the selector until every visible string, accessibility label, error, empty state, and validation message has a reviewed translation.

## First launch and persistence
- A dedicated full-screen language selection page blocks the application until a locale is selected.
- There is no skip, close, or dismiss action.
- Before authentication, the choice is saved in `localStorage.afg_language`.
- After authentication, the selected locale is saved to the `user_settings.locale` table and mirrored to `user_preferences.language` and `users.preferred_language`.
- The account preferences endpoint returns the canonical locale so an existing signed-in user can restore their previous choice.

## Direction, typography, and formatting
- `applyDocumentLocale` sets `<html lang>` and `<html dir>` together.
- Dari uses RTL; English uses LTR.
- Use CSS logical properties (`margin-inline`, `padding-inline`, `inset-inline`, `border-inline`) for new layout rules.
- Font stack uses the system UI fonts with Noto Sans Arabic and Vazirmatn fallbacks for Arabic-script content.
- `src/utils/i18n.ts` provides strict typed `translate()` lookup and locale-aware date, number, and file-size formatting using `Intl.DateTimeFormat` and `Intl.NumberFormat`.

## Build enforcement
- `npm run i18n:check` verifies identical dictionary keys and non-empty string values for every supported locale.
- `npm run build` runs the checker first through `prebuild`; missing or empty keys fail the build.
- GitHub Actions runs the locale checker and production build for pull requests targeting main.

## Important migration boundary
The strict dictionary checker guarantees dictionary completeness, not that every legacy component has stopped embedding literal UI text. Existing screens still contain some hard-coded labels and must be migrated to `translate(language, key)` or `translations[language].key` before claiming complete single-language coverage. New UI must not add inline mixed-language copy or silently fall back to English.
