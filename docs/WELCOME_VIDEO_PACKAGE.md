### Mandatory live capture preflight

1. Use a clean, non-personal production demo account with consented sample data.
2. Confirm provider health and a complete, non-empty response for each selected tool.
3. Confirm each saved item and conversation survives a page reload.
4. Confirm the exact language variant is consistent across the whole UI.
5. Capture the real deployed UI at native resolution; preserve original unedited recordings.
6. Save request IDs, model/provider IDs and a short capture log for each feature shot.
7. If any check fails, omit that shot. Never replace it with a mock, animation pretending to be a feature, or fake success state.

## 7. Site embedding specification

**Do not implement autoplay until actual video files, posters, captions and final destination URLs exist.** The current repository has language selection but no welcome-video player or video assets.

### First-launch flow

1. Show the existing mandatory language picker first.
2. Persist the selected locale; choose the matching EN or Dari welcome asset. Never mix UI languages.
3. Show Video 3 poster immediately. The player is lazy-loaded only after the user consents/enters the welcome view; `preload="none"`.
4. Start muted with captions enabled by default only when browser autoplay policy permits. If autoplay is blocked, show the poster and a clear Play control.
5. Primary CTA: “Enter AFG AI” / «ورود به AFG AI». Secondary CTA: “Watch the full story (60s)” / «تماشای داستان کامل (۶۰ ثانیه)» opens Video 1 in an accessible lightbox.
6. Respect `prefers-reduced-motion`: render the static poster and CTA; do not autoplay.
7. On media error, timeout, or unsupported codec, retain the poster and CTA. The welcome flow must never block app entry.

### Player and accessibility

- Use native `<video>` with `playsinline`, `muted`, `preload="none"`, poster and explicit caption tracks. Do not autoplay with sound.
- Provide keyboard-operable Play/Pause, captions, volume and close controls; visible focus indicators; Escape closes the lightbox; restore focus to the opener.
- Include a screen-reader text summary describing the actual actions shown; do not rely on visuals alone.
- Captions default on; user can turn them off. Supply EN and Dari caption tracks as separate localized assets.
- Avoid flashing; follow WCAG reduced-motion and contrast practices. Keep CTA text within safe areas on mobile.
- Use a static hero for reduced motion and low-bandwidth mode.

### Performance and privacy

- Ship compressed responsive posters (AVIF/WebP plus JPEG fallback), a low-bitrate mobile encode, and separate 4K/1080p/720p masters for external distribution.
- Lazy-load the player only when the welcome screen is visible. Do not preload the full video.
- Prefer self-hosted media or a privacy-reviewed host. If using an embedded third-party player, document its cookies/network requests and provide the necessary consent.
- Do not add per-user video analytics. If aggregate counters are approved, count only coarse events (start/completion) after opt-in and retain no IP, user ID, device fingerprint or playback timeline. Respect existing analytics opt-out.
- The player must fail open to the normal app; media errors must not break auth, routing or the language preference.

### Suggested component boundary (implementation task, not yet coded)

Create a dedicated `WelcomeExperience` component after final media delivery. Keep it outside chat state. Props should include locale, video/poster/caption URLs, reduced-motion preference, onEnter and onWatchFull. Add a tested feature flag so it can be disabled instantly. Do not add placeholder MP4 URLs or fake poster images.

## 8. Production checklist

### Pre-production
- [ ] Confirm launch URL, docs URL, privacy URL and launch date.
- [ ] Run the live feature preflight for each ⚠️ candidate and record evidence.
- [ ] Lock EN and Dari terminology; native Dari speaker reviews every line.
- [ ] Approve the final 60s/90s/15s scripts and storyboard.
- [ ] Choose and license music for YouTube, site, paid ads and social platforms; archive proof.
- [ ] Book EN and Dari voice talent or approve human-recorded internal VO.
- [ ] Create a sanitized demo account and resettable sample data.
- [ ] Confirm no private names, emails, API keys, tokens or user data appear.

### Capture
- [ ] Record real UI at 4K/60 where supported; capture original audio separately.
- [ ] Record each UI action in one uninterrupted take plus clean insert takes.
- [ ] Capture actual errors only when they occur naturally; never stage a false success.
- [ ] Save raw recordings, request IDs, provider/model IDs and capture notes.
- [ ] Capture a separate EN and Dari UI session; do not merely overlay translated text on a mismatched interface.

### Edit and sound
- [ ] Edit 4K master; 24fps cinematic sections and 60fps hero/UI shots only where source capture supports it.
- [ ] Use the locked palette: #05060A, #0DF2FF, #7C4DFF, #FFB86B, #F5F7FA.
- [ ] Use cubic-bezier(.2,.8,.2,1) motion language; no gratuitous bounce or spin.
- [ ] Keep on-screen copy ≤6 words and readable for at least one second per three words.
- [ ] Mix VO above music; target platform loudness and check true peak.
- [ ] Human-review EN and Dari captions against final picture.

### Export and publish
- [ ] Export 4K master, 1080p, 720p and vertical 1080×1920; create 1:1 LinkedIn crop.
- [ ] Export 1280×720 thumbnails under 2 MB, three concepts per video.
- [ ] Export EN/FA SRT and VTT; re-time after picture lock.
- [ ] Upload language variants with localized title, description, tags and pinned comment.
- [ ] Add YouTube chapters/cards/end screen and verify every destination URL.
- [ ] Run the eight-point quality gate in the source prompt before publishing.
- [ ] Publish only after product owner approval of the final picture and copy.

## 9. Update policy

- Any feature removed, disabled, materially changed or no longer supported in the production release triggers a re-cut or removal of that shot within **14 days** of the change being confirmed.
- Review every video before each major release and at least once every 30 days while the product is changing quickly.
- Store a manifest with each published video: product version, audit date, commit SHA, provider/model IDs (where relevant), capture date, locale, music license evidence, VO release, subtitle version and source footage path.
- Version naming: `AFG-Welcome-V1.0-EN-4K`, `AFG-Welcome-V1.0-FA-4K`, `AFG-Tour-V1.0-EN-4K`, etc. Increment patch for caption/metadata fixes; minor for shot swaps; major for narrative or feature-set changes.
- Maintain a public-facing “last reviewed” date in video descriptions. Never silently leave a stale feature claim online.
- If a feature is temporarily unavailable, replace the shot with another verified feature or cut it; do not use a coming-soon mockup.
