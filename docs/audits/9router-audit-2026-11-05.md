# گزارش ممیزی اولیه 9Router برای AFG AI

- تاریخ ثبت: 2026-11-05
- مخزن upstream: https://github.com/decolua/9router
- نسخه/وضعیت شاخه اصلی که در زمان بررسی مشاهده شد: `v0.5.112`
- هدف: ثبت یافته‌های اولیه برای تصمیم‌گیری درباره اتصال امن 9Router به AFG AI.
- دامنه: این سند گزارش ممیزی اولیه است، نه تأیید امنیت کامل پروژه و نه ممیزی خط‌به‌خط همه PRها.

## خلاصه اجرایی

1. ساخت Docker شاخه اصلی برای `linux/amd64` و `linux/arm64` در اجرای بررسی‌شده موفق گزارش شده بود.
2. PR مهم `#5425` قابلیت cache بلوک‌ها و cache پاسخ کامل را اضافه می‌کند.
3. طراحی کلید Full Response Cache در کد بررسی‌شده چند شناسه هویتی/نشستی را از کلید حذف می‌کند؛ این موضوع در استقرار چندکاربره ریسک بالقوه بازپخش پاسخ بین کاربران یا حساب‌ها ایجاد می‌کند و باید پیش از فعال‌سازی با بررسی call-site و تست ایزوله‌سازی اثبات/رد شود.
4. فایل‌های cache شامل متن کامل پاسخ هستند؛ باید محل ذخیره، مجوزهای فایل، چرخه حذف، دسترسی مدیریتی و رمزگذاری در حالت سکون بررسی شوند.
5. تا زمان رفع ابهام‌ها، Full Response Cache برای AFG AI غیرفعال بماند. Block Cache نیز فقط پس از بررسی تنظیمات، محدوده namespace و تست امنیتی فعال شود.

## یافته‌های فنی

### 1. PR #5425 — filesystem token cache و response cache

لینک: https://github.com/decolua/9router/pull/5425

در فایل `open-sse/rtk/fsCache.js` موارد زیر بررسی شد:

- cache بلوک‌ها با کلید مبتنی بر hash و namespace.
- cache پاسخ کامل JSON و SSE.
- کلید پاسخ با ترکیب provider، model، source format، stream و بدنه canonical‌شده درخواست ساخته می‌شود.
- فیلدهایی مانند `user`, `sessionId`, `conversationId` و `metadata` از بدنه canonical حذف می‌شوند.
- متن کامل پاسخ در فایل ذخیره می‌شود و cache hit با هدر `X-9Router-Cache: HIT` مشخص می‌شود.
- TTL پیش‌فرض گزارش‌شده ۲۴ ساعت و سقف حجم پیش‌فرض ۵۰۰ مگابایت است.

**ریسک حریم خصوصی/جداسازی کاربران:** حذف شناسه‌های کاربر و نشست از cache key فقط زمانی ایمن است که پاسخ کاملاً مستقل از هویت، مجوزها، حساب upstream، ابزارها و داده‌های خصوصی باشد. این استقلال هنوز با بررسی مسیر فراخوانی و تست عملی اثبات نشده است. بنابراین این مورد را «ریسک بالقوه مهم، نیازمند تأیید» طبقه‌بندی می‌کنیم، نه آسیب‌پذیری اثبات‌شده.

**ریسک نگهداری داده:** پاسخ‌ها به‌صورت متن در فایل ذخیره می‌شوند. باید دسترسی فایل‌ها، محافظت از volume، حذف امن، مدت نگهداری و احتمال درج داده‌های حساس بررسی شود.

**ریسک پاسخ‌های ابزارمحور:** باید مشخص شود درخواست‌های دارای tool calls، ابزارهای دارای اثر جانبی، پاسخ‌های وابسته به زمان و درخواست‌های شخصی‌سازی‌شده از cache مستثنا هستند یا خیر. تا روشن‌شدن این موضوع، cache پاسخ کامل برای چنین درخواست‌هایی نباید فعال شود.

**رفتار پاک‌سازی:** بررسی اولیه نشان داد زمان انقضا هنگام خواندن بررسی می‌شود؛ پاک‌سازی بر اساس زمان دسترسی واقعی LRU به نظر نمی‌رسد، چون mtime در هر hit به‌روزرسانی نمی‌شود. این موضوع باید با تست حجم/TTL و کد مسیر prune تأیید شود.

**ملاحظه هزینه:** تشخیص قابلیت مدل‌ها ممکن است درخواست واقعی به provider بفرستد و سهمیه را مصرف کند. پیش از فعال‌سازی باید تعداد probeها، نوع probe، هزینه احتمالی و امکان opt-in/تأیید مدیر مشخص شود. هیچ عدد ثابت یا هزینه قطعی از این ممیزی نتیجه‌گیری نمی‌شود.

### 3. PRهای سهمیه و منطقه

- PR #5462: https://github.com/decolua/9router/pull/5462 — قفل سهمیه و فعال‌سازی مجدد زمان‌بندی‌شده.
- PR #5463: https://github.com/decolua/9router/pull/5463 — اصلاحات منطقه Kiro.

این PRها برای مسیر مدیریت سهمیه و سازگاری provider مهم‌اند؛ اما پیش از پذیرش باید race condition، قفل توزیع‌شده، رفتار چند replica، reset quota و خطاهای زمان‌بندی بررسی شوند. این گزارش آن‌ها را تأییدشده اعلام نمی‌کند.

## وضعیت CI و دامنه بررسی

- در بررسی اولیه، صفحه نخست PRهای باز (تا ۱۰۰ مورد اخیر) و چند PR منتخب به‌صورت عمیق‌تر مرور شدند؛ این کار معادل بررسی تمام PRهای مخزن نیست.
- برای head بررسی‌شده PR #5425، در داده‌ای که آن زمان دریافت شد Check Run قابل اتکایی برای تأیید موفقیت مشاهده نشد؛ بنابراین نباید آن را CI-passed تلقی کرد.
- موفقیت Docker build شاخه اصلی، به‌تنهایی به معنی موفقیت همه تست‌ها یا سلامت امنیتی نیست.
- وضعیت CI هر PR باید با head SHA همان PR و تازه‌ترین check runs/statuses مجدداً بررسی شود؛ نتیجه یک PR را نمی‌توان به PR دیگر تعمیم داد.

## توصیه‌های اجرایی برای AFG AI

| قابلیت | تصمیم موقت |
|---|---|
| Block Cache | فقط پس از بررسی namespace، صلاحیت داده و تست ایزوله‌سازی |
| Full Response Cache | غیرفعال تا اصلاح/اثبات جداسازی هویت و bypass درخواست‌های حساس |
| Tool-call caching | غیرفعال مگر برای ابزارهای صریحاً امن و idempotent |
| Model capability probes | نیازمند opt-in، محدودیت نرخ و هشدار مصرف سهمیه |
| Usage/token savings | تفکیک مقدار واقعی provider از مقدار تخمینی؛ بدون ادعای صرفه‌جویی قطعی |
| Cache storage | حداقل‌سازی داده، محدودیت دسترسی، TTL، پاک‌سازی و محافظت از دیسک |

## چک‌لیست ادامه ممیزی

- [ ] دنبال‌کردن مسیر کامل فراخوانی Full Response Cache و تمام bypassها.
- [ ] تست دو کاربر/دو حساب با درخواست یکسان برای رد یا اثبات cross-user cache hit.
- [ ] بررسی tool calls، streaming، خطاهای upstream و پاسخ‌های وابسته به زمان.
- [ ] بررسی مجوز فایل، رمزگذاری، حذف و دسترسی endpointهای آمار cache.
- [ ] بررسی concurrency و multi-replica برای quota locks و scheduled reactivation.
- [ ] مرور همه PRهای باز و بسته به‌صورت صفحه‌بندی‌شده، اولویت‌بندی‌شده بر اساس امنیت و اثر عملیاتی.
- [ ] بررسی CI هر PR بر اساس head SHA و بررسی وابستگی‌ها و Docker image.

## محدودیت و شفافیت

این گزارش یافته‌های بررسی اولیه را ثبت می‌کند. هیچ کدی در مخزن upstream `decolua/9router` تغییر نکرده، هیچ PR آن مخزن merge نشده و هیچ deployment انجام نشده است. ثبت این گزارش در AFG AI نیز به‌خودی‌خود هیچ قابلیت 9Router را در محصول فعال نمی‌کند.
